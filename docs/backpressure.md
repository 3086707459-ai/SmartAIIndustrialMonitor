# 有界传递与背压契约

## 数据链路

采集线程不再为每条采样投递 Qt 排队事件。`sampleAcquired` 的 DirectConnection 只调用加锁的信箱入口；SQL、推理与 Device 状态修改仍在各自所属线程执行。消费者用定时器取有限批次，释放锁后处理。

| 路径 | 默认待处理上限 | 消费方式 | 满载策略 |
| --- | ---: | --- | --- |
| 采集 → 持久化 | 8192 条 | 10 ms 定时器，每次最多 256 条 | 等待空位最多 5 ms；仍满则拒绝新条目并计数 |
| 采集 → AI | 2048 条 | 10 ms 定时器，每次最多 128 条 | 淘汰最旧待处理采样并计数 |
| 采集 → 界面模型 | 1024 个设备最新值 | 100 ms 定时器，每次最多 256 个 | 同设备覆盖旧值；新设备超容量淘汰最早进入的键 |
| AI → 界面分析结果 | 1024 个设备最新结果 | 主线程刷新时取出 | 同设备覆盖；超容量淘汰并计数 |
| 相机 → 界面 | 1 帧 | 主线程刷新时取出 | 只保留最新帧，计替换次数 |
| 模型 → 告警／预测／异常存储 | 2048 条记录 | 10 ms 定时器，每次最多 16 条 | 不阻塞 GUI；拒绝新记录并计数 |

前三项容量可在 `pipeline.persistenceCapacity`、`pipeline.aiCapacity`、`pipeline.uiCapacity` 中配置，范围钳制为 1～65536。容量在构造时确定，修改需要重启。降低容量前应按实际设备数和处理耗时验证，不应直接复制压测配置。

持久化队列等待会延缓采集线程的 socket 消费；`QTcpSocket` 的读缓冲限制为 64 KiB，进一步让 TCP 接收窗口对上游施加流控。模拟网关限制每个客户端的待发送字节为约 4 MiB，持续阻塞时断开客户端。修复了这一断开分支中同步 `disconnected` 信号导致的迭代器失效。

容量指信箱中的待处理条目，不包括已经取出的有限批次、SQLite 的批写缓冲和内核 TCP 缓冲。SQLite 批写缓冲另有 20000 条上限。未实现应用层序列号确认、磁盘溢写和重放，所以这是**有界资源与可观察损失策略，不是断网／锁库条件下的零丢失承诺**。

容量按条目而非字节限制；协议虽然有单帧长度上限，超长设备标识仍会显著增加每条内存。当前内存验收覆盖正常尺寸遥测，不代表已经验证对抗性报文下的内存预算。

## 指标定义

`ApplicationController::pipelineStatistics()` 暴露采集数、已提交行数、存储失败／过滤数、各采样信箱以及派生记录的计数。运行中每个信箱分别加锁读取，不是全系统原子快照；最终核对需要先停止上游并排空。

- `offered`：进入信箱入口的次数。
- `taken`：已出队的条目数，不等于已完成推理或已写入数据库。
- `rejected`：满载等待超时，或关闭后的拒绝。
- `evicted`：为接纳新值而淘汰旧值。
- `coalesced`：同设备最新值替换；这是显示策略，不算落库丢失。
- `cancelled`：关闭时明确取消的待处理工作。
- `waits / waitMs`：生产者因满载等待的次数／总毫秒数。
- `highWater`：队列深度峰值。
- `maxLatencyMs / p95LatencyUpperMs`：入队到出队的等待延迟；P95 为固定直方图桶的上界，不含入队前阻塞、SQL 或推理时间，不能写成端到端 P95。

采样信箱满足：`offered = taken + depth + rejected + evicted + coalesced + cancelled`。测试验证容量和计数守恒。GUI 状态定时器在损失计数增加时写日志并显示提示；累计计数也用于压力验收，不依赖临时提示是否被看到。

## 关闭、故障与剩余限制

先停止并等待采集，再停止 AI。主线程应用最后的设备／分析值快照，此时持久化线程仍可接收派生记录；最后关闭存储入口、排空采样、提交末批、处理已接收的记录，再释放数据库。

AI 待分析采样可在关闭时取消并计数；界面分析结果在阻塞期间可被更新结果覆盖，因此数据库中的 Prediction 不应解释为每一次 AI 推理的审计记录。

SQL 提交失败的批次计入损失，后续写入进入 5 秒冷却，避免对每条记录重复等待数据库锁。关闭时不再为每个队列批次做一次提交尝试；锁库回归用例验证 1024 条待处理样本被完整计入损失，并在 13 秒测试上限内返回。当前 SQLite 的 busy timeout 是 5 秒。

生产线程仍采用协作式停止：正在执行的模型、磁盘调用或人为提交的大量配置／查询请求没有全局硬实时截止保证。压测脚本的进程看门狗只用于判定测试失败，不会在生产代码中强杀 QThread。数据通道有界不代表所有用户控制请求都已限流。

物理阈值在持久化线程取出采样时判定；配置更新与采样不是全局原子切换。已进入批写缓冲的状态不会随之后的阈值更新改变。
