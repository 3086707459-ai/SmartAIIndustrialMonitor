# C++ / Qt 实习作品说明

## 项目定位

建议项目名：**基于 Qt 的工业设备监控与异常诊断平台**。

展示重点是 C++ 资源管理、Qt 事件循环与跨线程信号槽、TCP 字节流协议、SQLite 事务，以及从测试失败定位真实缺陷的能力。AI 是诊断模块，不能替代客户端工程基本功。

## 五分钟演示脚本

1. 启动前执行一键验证，展示测试输出。说明默认采用模拟设备与启发式诊断。
2. 启动应用，展示设备列表、实时曲线、连接状态和样本增长；解释为何显示刷新与采样频率分离。
3. 选择设备并使用故障模拟入口，观察告警、状态和诊断变化；解释物理阈值与诊断如何合并。
4. 展示 SQLite 历史数据，说明事务批写与设备外键；用 `test_database` 展示第二批失败时第一批也被回滚。
5. 展示协议拆包测试、线程重启测试，最后正常关闭应用。报告导出可作为额外演示，但应在投递前手动检查导出文件内容与排版。

录制时保留一次完整启动和退出过程，不要只展示静态界面。真实模型、设备数量、运行时长、吞吐与时延，只写实际测得并保留证据的数据。

下列内容是项目当前能力的描述。投递前应理解代码、亲自复现测试，再按自己实际负责的工作调整措辞。

> - 实现长度前缀 TCP 协议的半包与粘包解析，完善异常帧恢复、数值校验和接收缓冲边界，并通过逐字节切分等回归用例验证。
> - 使用 SQLite 事务批写、外键与版本迁移管理历史数据；完善工作线程定时器归属、资源释放与重启流程。
> - 建立 CMake / CTest 验证流程，包含 10 个测试目标、77 个用例，覆盖协议、设备、诊断、数据库、线程、热更新、真实链路过载及 UI 冒烟测试。
> - 使用有界队列与按设备合并的最新值信箱分离采集、分析、存储和界面刷新，实现满载等待、超时拒收与可核对的损失计数；通过锁库、UI 阻塞和慢客户端测试验证故障行为。
> - 在 16 台模拟设备、800 条／秒负载下完成 30 分钟持续测试，144 万条采样发送、接收与落库一致，存储和 AI 无丢失；保留 JSON 指标、内存曲线与源码哈希用于复查。

不要写“准确率 99%”“支持万级并发设备”“工业级稳定运行”“独立训练 YOLO”，除非另有真实实验和可复现材料。

## 面试需要讲清楚的六个问题

| 问题 | 应结合项目讲述的内容 |
| --- | --- |
| TCP 为什么需要拆包？ | TCP 提供字节流；固定头和长度字段；保留未完成帧；垃圾数据后如何找回帧头 |
| QThread 对象和工作对象分别在哪个线程？ | 创建线程、线程亲和性、事件循环、QueuedConnection、定时器父子关系 |
| 为什么不能用 terminate 解决退出卡顿？ | 任意中断可能打断事务或锁持有；当前协作式停止仍依赖任务最终返回 |
| 为什么选择事务批写？ | 减少提交成本；跨分块原子性；失败重试与积压上限的区别 |
| GUI 为什么只接收合并后的数据？ | 最新值信箱同时限制设备键数和消费批次；比较合并、淘汰与落库丢失；解释为何只限发信号频率不能保证队列有界 |
| 没有模型文件时如何处理？ | 显式后端标识、启发式预测与统计检测、无足够样本不宣称健康、缺少真实模型验证 |

可准备的故障定位案例：`Status::ok()` 默认错误码不为零；定时器没有随 worker 迁移；合法粘包超过单帧上限被整体丢弃；Warning 升级 Fault 被重复告警抑制；数据库父记录缺失导致外键失败；慢客户端断开导致迭代器失效；首次输出路径错误写入父目录。讲述顺序为“现象 → 最小复现 → 根因 → 修复 → 回归测试”。
