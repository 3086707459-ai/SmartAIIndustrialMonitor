# C++ / Qt 医疗客户端实习作品说明

建议展示名：**MedSignal Workbench：基于真实公开数据的医疗生理信号回放与分析工作台**。

## 五分钟演示

1. 展示 PhysioNet 原始页面、作者、许可与 SHA-256，说明使用真实记录，离线演示包含第 01 段与低覆盖的第 05 段。
2. 打开 `MedSignalWorkbench.exe`，播放 ECG、PPG、呼吸三通道，切换速度、暂停和拖动；说明 125 Hz 波形与 1 Hz 数值的同步方式。
3. 定位到 111 秒，展示真实缺失 SpO2 / PULSE 没有被填成零；切换至 05，在 Window review 筛选未计分窗口，双击定位完整 30 秒区间。
4. 导出评测 JSON / CSV，展示 53 段、848 窗口、728 可评测、85.85% 覆盖率与 1.23 次/分 MAE；检查 CSV 保留全部未计分窗口及原因，主动打开 05、13、23 的失败案例。
5. 展示严格构建、102 个回归用例、完整真实数据 CI 与分发包验收。根据岗位再展示独立 TCP / SQLite 工程底座。

## 简历表述

请先亲自复现并理解代码，再按实际负责的部分改写：

> **医疗生理信号回放与分析工作台｜C++17、Qt 6 Widgets / Charts、QtConcurrent、CMake**
>
> - 基于 PhysioNet BIDMC 53 段真实医疗记录实现 ECG、PPG、呼吸同步回放，支持多倍速、暂停定位、人工呼吸标注叠加和监护仪数值展示。
> - 实现有界文件导入、严格字段与时间轴校验、发布方 SHA-256 核验，处理真实缺失值、CSV 时间舍入、标注乱序／重复和数值起点偏移。
> - 实现固定自相关呼吸率基线，以双人标注窗口计数为参考，完成 848 个窗口评测；可评测 728 个、覆盖率 85.85%、MAE 1.23 次/分，保留逐记录误差及拒绝原因。
> - 建立 12 个 CTest 目标、102 个回归用例及 Windows CI，覆盖医疗导入与 UI、原工程协议／线程／数据库；分发包包含可追溯真实数据与运行库，并验证 SDK PATH 隔离下的原生界面。

原工程底座的多线程、有界背压、TCP、SQLite 能力可单独写一条，但必须说明它尚未承载真实医疗设备实时流。历史 30 分钟模拟链路压力结果也应标注对应历史版本，不能写成患者数据长时间在线监护。

## 面试重点

| 问题 | 项目中可展示的证据 |
| --- | --- |
| 为什么选择该数据集？ | 官方来源、开放许可、真实波形、双人标注、版本固定和字节级完整性 |
| 为什么不能把 NaN 变成 0？ | 原始 111 秒缺失值；未知状态与正常测量的区别 |
| 为什么时间不能直接用 CSV 差分？ | 五位有效数字舍入会产生重复时间戳；使用明确的 125 Hz 采样契约 |
| GUI 如何保持可操作？ | QtConcurrent 值返回，不在导入任务里捕获窗口；单调时钟驱动播放；显示窗口有界 |
| MAE 的分母是什么？ | 728 个可评测窗口；同时公布总计 848 个及覆盖率，拒绝不等于正确 |
| 有没有参考信息泄漏？ | 基线只读 RESP；标注随后进入评分，回归测试验证改变标注不改变估计 |
| 最明显的不足？ | 05 的低覆盖、23 的高误差；尚无外部数据集、真实医疗设备和临床验证 |

不要声称训练了临床模型、达到临床标准、实现心律失常诊断或保证获得实习。作品的说服力来自可复现的正确性、明确的边界，以及你能解释的工程取舍。
