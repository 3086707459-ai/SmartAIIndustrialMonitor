# 质量审查记录（更新于 2026-10-15）

## 初始状态

模块划分完整，但源码与测试、注释之间存在多处不一致。默认构建因 3 个缺失测试文件失败；继续编译后，主程序、模拟器和 UI 还存在接口与头文件错误。因此初始状态不能作为“已完成项目”直接展示。

## 本轮修复

| 问题 | 改动与证据 |
| --- | --- |
| `Status::ok()` 返回失败状态 | 成功状态初始化错误码为 0；common 测试验证 |
| 缺测试源、依赖和接口漂移 | 补 AI / 协议 / 数据库测试，增加 Qt Test 链接，修正现有用例与接口 |
| UI 与入口编译失败 | 修正头文件、名称作用域、重载冲突、const 用法与方法调用 |
| 定时器停留在创建线程 | 将采集、持久化和 AI 的成员定时器设置为工作对象的子对象 |
| 工作对象和窗口未释放 | 线程停止后迁回控制线程，线程池释放工作对象，控制器释放窗口 |
| 同线程阻塞调用可能死锁 | 同线程直接执行；测试嵌套调用、重启与自停止 |
| 合法大批粘包被丢弃 | 分段填充和解析有界接收缓冲；允许一次读取多个合法大帧 |
| 垃圾数据尾部的 `S` 被丢弃 | 保留可能与下一次读取的 `A` 组成帧头的尾字节 |
| 缺失数值被当作零值 | 拒绝缺失、非数值、非有限遥测字段 |
| 告警抑制吞掉严重度升级 | 仅对相同严重度抑制；验证 Warning → Fault 新告警 |
| 首次启动与零超时状态错误 | 未收到样本时 latest 无效；超时边界使用包含等号比较 |
| SQLite 内存模式路径错误与缺设备外键 | 特判 `:memory:`；工作线程初始化时注册配置设备；允许空 IP 字符串 |
| 无 UI 控制器启动崩溃 | GDB 定位空窗口指针；采集状态更新增加窗口存在检查 |
| 环境变量不能覆盖 camelCase 配置项 | 按 JSON 既有键逐层做大小写无关匹配 |
| 趋势图没有接入实时采样、卡片裁切 | 图表连接主线程采样信号，启动时选择设备，卡片按可视宽度排布；UI 测试验证曲线点数 |

测试中原有的部分期望也需要修正：配置只定义电压 Warning 边界，不应凭空要求电压 Fault；诊断 Fault 同时要求低健康度和高失败概率，不能只设置健康分数。没有为了让测试通过而新增未经定义的物理阈值。

## 验证范围

- 本机 Windows、Qt 6.8.3、MinGW 13.1，默认无 ONNX / OpenCV 模式。
- 2026-10-15 基线为 10 个 CTest 目标、77 个行为用例；2026-10-22 增至 84 个。包括真实本机 TCP、SQLite、锁库／过载和离屏 UI。
- `scripts/verify.ps1` 和 `demo` preset 提供独立构建目录及警告视为错误的重复验证入口。
- 本轮严格构建与 10 组完整回归通过，JUnit 记录为 `build/acceptance/regression-20261015.xml`，详细测试输出在 `build/demo/Testing/Temporary/LastTest.log`。`build/verify.log` 为前一轮全量构建记录。
- 不等同于代码覆盖率、性能基准、持续集成平台运行结果、真实硬件验收或所有 UI 功能验收。

## 第二轮改进（2026-10-13）

- 移除 AIWorker 的 DeviceManager 指针；分析使用工作线程独立维护的阈值副本，报告接收主线程生成的值快照。
- 配置 typed views 改为加锁返回副本；AI 状态字符串使用锁保护，跨线程采样计数、诊断计数与可用状态使用原子变量。相机开关经排队调用进入 AI 线程。
- 每条 SensorData 保存采样入队后、持久化线程处理时的物理阈值状态。更新阈值不会重新解释已入缓冲的历史记录；AI 预测仍独立保存在 Prediction 表。
- 设备与阈值更新同步到工作线程；新增设备先 upsert 外键父记录，移除或禁用后拒收迟到采样，移除记录保留历史并标为 disabled。空数组可清空设备；模拟网关同步更新设备列表。
- 修复诊断耗时计时器未启动、数据不足仍发布空诊断、数据库行数只在启动时显示的问题。
- 报告保留真实内存窗口时间与样本数，整厂范围不再被解析成首台设备；界面和导出文本明确当前为实时快照，移除未实现的历史周期选项。
- 新增 6 个回归用例：保留窗口计数、采集时状态、AI 配置副本、配置并发读取、报告快照生命周期、完整链路热更新。

## 第三轮改进（2026-10-15）

- 采集到落库、AI、GUI 的有界采样信箱；AI 结果与视觉帧采用有界最新值信箱；告警／预测／异常存储使用独立有界队列。采集统计和数据库行数改为定时读取，避免按 socket read 或每次提交投递 GUI 事件。
- 明确不同路径的等待、拒收、淘汰、合并和取消策略，暴露容量峰值、生产者等待、计数守恒与出队延迟指标；SQL 失败批次也计入损失。详细语义见 [背压契约](backpressure.md)。
- 关闭先汇合生产者，再应用主线程的最后快照，最后排空存储；锁库时不再为每个采样批次重复等待。取消尚未分析的 AI 采样会计数，不宣称所有采样都完成推理。
- 修复 TcpServer 慢客户端断开时迭代器失效；增加实际慢连接与健康连接并存的回归测试。
- 新增持续真实 TCP 压力工具及进程看门狗、机器可读指标、数据库一致性验收、可复现配置与被测二进制哈希。
- 发布包与本机无 SDK PATH 原生 GUI 验收通过；发现并修复输出数据库逃逸指定 data root 的错误，数据库／日志／报告输出改用专用写入路径解析。详见 [部署验收](deployment-acceptance.md)。
- 新增 11 个行为用例；压力与部署探针独立于默认 CTest，不计入这 77 个用例。
- 可随源码保存的完整回归记录：[regression-20261015.xml](acceptance/regression-20261015.xml)。
- 正式 30 分钟压力验收已通过：800 条／秒、144 万条采样，发送／接收／落库一致，存储和 AI 无丢失；最终报告与时间线见 [压力验收](stress-acceptance.md)。

## 第四轮改进（2026-10-22）

- 修复已经接收过遥测的设备超时离线后，被迟到诊断重新标为在线的问题；停用设备也拒绝诊断与告警更新，重新启用后必须等待遥测。
- 同轮预测与异常结果通过 `Device::applyAnalysis` 一次性更新，控制器只向界面发布被接受的分析；避免两个组件交替承担 Fault 状态时出现中间 Normal 状态和重复告警。
- 异常结果立即参与状态计算，同严重度持续异常不重复触发状态告警；告警描述区分物理越限、模型诊断与异常检测原因。
- 超时／停用清除诊断缓存，保留历史遥测；离线超时与告警抑制使用单调计时，不依赖系统墙上时钟差值。
- 新增 6 个设备行为用例和 1 个控制器集成用例，总计 84 个用例。原有 30 分钟压力报告明确绑定历史版本，不视作修改后版本重新完成长测。
- 本轮只隔离设备处于离线／停用状态时到达的结果；跨重连、跨配置版本仍缺少采集会话编号，不能保证已恢复在线后到达的旧会话结果被识别。单调超时仍依赖主线程定时器得到执行，不提供 GUI 阻塞下的硬实时离线检测。
- 修改后 60 秒压力回归通过，48,000 条采样收发与入库一致；[压力 JSON](acceptance/stress-20261022.json) 与 [完整回归 JUnit](acceptance/regression-20261022.xml) 随源码保存。

## 下一阶段优先事项

### 医疗主题迁移（2026-10-26）

- 新主程序 `MedSignalWorkbench` 通过独立 `src/medical` 模型读取真实 PhysioNet BIDMC CSV；保留旧工程底座，未把旧电机字段重命名为生命体征。
- 完成 53 段、159 个原始文件的发布方哈希核验及固定 RESP 基线评测。848 个窗口中 728 个可评测，MAE 1.23 次/分、覆盖率 85.85%；未估计和参考重复的窗口均公开。
- 真实数据发现的时间舍入、NaN、标注重复／乱序与数值起点偏移均有明确处理和记录。导入器内嵌发布方哈希清单，拒绝被修改的源文件。
- 新增 9 个医疗解析／评测用例和 2 个医疗 UI 用例；总计 12 个目标、95 个用例。医疗版部署探针替换当前包的工业探针，旧验收单独保留为历史。
- 医疗模块没有训练模型、真实器械接入或临床验证。原工程的跨重连会话、原始流告警、持久化重放等边界仍在；不能以新主题或数据集评测消除这些限制。

医疗功能的下一步优先级为低质量信号拒绝策略、05／13／23 等难例分析及独立数据集测试。下列工程底座事项仍保留。

这些问题尚未在本轮闭环，不能据此声称已经达到生产级质量。

1. **并发契约的剩余边界。** 当前消除了 AI 对设备对象的直接跨线程读取；少数未被控制器使用的工作线程状态 getter 仍应约束为所属线程访问。配置更新与采样来自不同事件来源，生效边界为各工作线程处理配置事件的时刻，不是跨线程全局原子切换。
2. **历史统计语义。** 历史状态现在表示持久化处理时的物理阈值判定，不能等同于包含 AI 升级的全部告警状态；需要进一步验证告警时间线、可用率定义与历史报告。设备告警仍基于主线程收到的合并采样，短暂越限可能仅出现在全量历史中，应补原始流事件检测与对应测试。
3. **配置热更新边界。** 设备、阈值、模拟采样间隔、AI 窗口与推理频率、落库间隔可更新；监听端点、数据库文件和模型后端需重启。高频配置变更仍需压力验证，严格切换可引入配置版本号。
4. **可靠交付与退出期限。** 主要数据通道已有硬容量限制及可观察损失；尚无应用层确认／重放或磁盘溢写，不承诺故障下零丢失。协作式停止仍依赖模型和系统调用返回，用户配置／查询请求也未全面限流，不能用强杀线程替代取消契约。
5. **时间与报表。** SQL 中 ISO 时间字符串尚未统一为 UTC，跨时区查询边界需要迁移方案。PDF、Markdown 与长报告需独立验证内容、换页和写入失败处理。
6. **模型证据。** 仓库没有训练脚本、权重、数据集与评估结果；代码中提到这些材料的注释不构成已实现证据。可选后端需要单独构建测试与实测。
7. **分发与自动化。** 本机隔离打包已验收；2026-10-18 补充 Windows CI 工作流并通过完整本机脚本验收，远程结果仍须按对应提交核实。还需真实干净 Windows 虚机／第二台电脑与故障恢复演示录像。持续测试的当前证据及范围见 [压力验收](stress-acceptance.md)，不能从单机单一负载外推多日运行或真实硬件规模。

优先把以上工程问题逐项解决，再考虑新增协议、更多图表或模型。对实习面试而言，一个能够复现、解释并验证的可靠数据链路，比无法证明的大量功能更有说服力。
